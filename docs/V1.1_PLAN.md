# ArchiveLens v1.1 Development Plan

Tracking issue: #1

Target version: **1.1.0**

This document is the implementation plan for the first major feature expansion after ArchiveLens v1.0.0. It is intended to be read by maintainers and by Codex before code changes are made.

## 1. Release goal

ArchiveLens v1.1 should evolve from a focused ZIP/CBZ image viewer into a broader **archive image and comic viewer** while preserving the strengths of v1.0:

- local-only operation;
- read-only archives;
- no full-archive extraction into a user-visible folder;
- lazy image loading;
- bounded memory use;
- background decoding;
- recoverable errors;
- portable Windows packaging and release verification.

The v1.1 user-facing scope is:

1. Windows installer in addition to the existing portable package.
2. RAR / CBR support.
3. 7Z support.
4. Password-protected ZIP/CBZ, including traditional encryption and AES where supported.
5. Password-protected 7Z and RAR where supported by the selected backends.
6. Animated GIF playback.
7. Lazy thumbnail sidebar.
8. Comic double-page mode.
9. Left-to-right and right-to-left reading direction.
10. Persistent non-sensitive viewer preferences.
11. CI/release hardening for the new dependencies, backends and installer.

## 2. v1.0 baseline that must be preserved

The current application already has a useful separation of responsibilities:

- `archive/` contains the archive provider abstraction and ZIP implementation.
- `image/` contains in-memory Qt image decoding, worker logic and an LRU cache.
- `ui/` contains the main window, toolbar and `QGraphicsView`-based image viewer.
- `config.py` centralizes resource limits.
- PyInstaller builds a Windows x64 portable package.
- CI runs source tests and packaged verification.

The v1.1 implementation should extend this architecture instead of bypassing it.

In particular, v1.0 already has:

- `ArchiveProvider`;
- `ArchiveEntry`;
- background loading with stale-request protection;
- decoded-image LRU cache;
- previous/next prefetch;
- ZIP bomb / image-size safeguards;
- source archive immutability tests;
- release manifests/checksums/self-test infrastructure.

These are regression requirements, not disposable implementation details.

## 3. Architecture direction

### 3.1 Archive provider registry/factory

The current worker directly constructs the ZIP provider. v1.1 must remove that coupling before adding formats.

Target structure:

```text
archive/
    base.py
    factory.py
    capabilities.py
    credentials.py
    zip_provider.py
    sevenzip_provider.py
    rar_provider.py
```

Conceptually:

```text
ArchiveProvider
├── ZipArchiveProvider
├── SevenZipArchiveProvider
└── RarArchiveProvider
```

The worker and UI must not contain format-specific archive logic beyond displaying format names/capabilities when necessary.

Suggested capability metadata includes:

- format name;
- supported filename extensions;
- password support;
- random-access characteristics;
- solid-archive behavior;
- optional backend availability state.

Provider capabilities should influence prefetch behavior. ZIP can usually tolerate aggressive random access; solid 7Z/RAR archives may not.

### 3.2 Structured archive errors

Do not use localized error strings as control flow.

Introduce structured errors such as:

- `PasswordRequiredError`;
- `BadPasswordError`;
- `UnsupportedEncryptionError`;
- `CorruptedArchiveError`;
- `ResourceLimitError`;
- `ProviderUnavailableError`.

The UI can translate these into friendly Traditional Chinese messages while worker/provider logic remains explicit.

### 3.3 Credentials

Archive passwords are sensitive ephemeral session state.

Rules:

- keep them in memory only;
- never persist them to QSettings;
- never write them to logs;
- never include them in command-line arguments;
- avoid dataclass/debug representations that can accidentally expose them;
- clear references when changing archives and on shutdown.

A shared `ArchiveCredentials` or archive-session abstraction should be used by ZIP/7Z/RAR providers rather than format-specific password plumbing in the UI.

## 4. Archive formats

### 4.1 Password ZIP / CBZ

Work item: #3

Requirements:

- preserve existing plain ZIP/CBZ behavior;
- support traditional ZipCrypto reads;
- support WinZip AES if the selected dependency passes packaging/license review;
- present a Qt password dialog on demand;
- support retry after a wrong password;
- allow Cancel without crashing or leaving the worker in a bad state;
- share the session password with prefetch without exposing it in logs.

The UI should not care whether the archive uses ZipCrypto or AES.

### 4.2 7Z

Work item: #4

Requirements:

- add `.7z` to all open paths and drag/drop filters;
- support plain and encrypted archives when supported by the chosen library;
- keep extraction in memory when possible;
- do not leave a full extracted directory behind;
- detect or model solid-archive cost;
- use conservative prefetch for expensive solid archives;
- preserve Unicode paths and natural ordering.

A library such as `py7zr` is a likely candidate, but implementation should be based on tested packaging behavior, not assumption.

### 4.3 RAR / CBR

Work item: #5

RAR is the highest-risk v1.1 backend because parser behavior, decompression backend, PyInstaller packaging and redistribution licensing must all succeed together.

Before the final provider implementation, run a backend spike that verifies:

- RAR4;
- RAR5;
- Unicode paths;
- password-protected RAR;
- solid archives;
- single-entry reads;
- Windows packaged executable discovery of the backend;
- installer redistribution rights and notices.

The final Windows release must not require end users to manually install WinRAR/unrar/7-Zip or modify PATH.

`.cbr` should map to the same provider.

## 5. Password dialog flow

Recommended flow:

```text
Open archive
  ↓
Provider detects encrypted content
  ↓
PasswordRequiredError
  ↓
Worker reports structured credential request
  ↓
UI displays PasswordDialog
  ↓
User enters password
  ↓
Current archive session receives credential
  ↓
Retry requested page
```

Wrong password should produce a recoverable retry path rather than closing the archive.

Dialog requirements:

- password field;
- masked input;
- Show Password checkbox;
- OK;
- Cancel.

Do not add permanent password storage in v1.1.

## 6. Animated GIF

Work item: #6

v1.0 displays the first GIF frame. v1.1 should play animated GIFs from archive bytes without temporary files.

Preferred Qt approach:

- `QByteArray` / `QBuffer` owns the in-memory bytes;
- `QMovie` performs animation decoding;
- frame changes update the current graphics item;
- the existing viewer retains fit, zoom, pan and fullscreen behavior.

Do not default to unbounded all-frame caching.

When leaving a GIF page, opening a new archive, or shutting down:

- stop the movie;
- release buffers;
- disconnect/update safely so stale frames cannot replace the current page.

## 7. Thumbnail sidebar

Work item: #7

Add an optional lazy thumbnail sidebar, preferably based on `QListView` + model/delegate.

Recommended defaults:

- target thumbnail dimension: roughly 144 px;
- separate thumbnail cache: roughly 64 MiB;
- full-image cache remains independently bounded.

Rules:

- do not decode all full-resolution pages at archive open;
- prioritize visible thumbnail rows;
- allow a small look-ahead window;
- cancel/deprioritize stale requests during fast scrolling;
- synchronize current page selection;
- clicking a thumbnail navigates directly to that page;
- `T` toggles the sidebar.

For expensive solid archives, thumbnail scanning must respect provider capabilities and remain bounded.

## 8. Comic reading mode

Work item: #8

### 8.1 Display modes

v1.1 supports:

- Single Page;
- Double Page.

Continuous vertical reading is explicitly deferred.

### 8.2 First page as cover

With cover mode enabled:

```text
1
2 + 3
4 + 5
6 + 7
...
```

Odd final page counts must be handled safely.

### 8.3 Reading direction

Support:

- Left to Right (LTR);
- Right to Left (RTL).

Keep logical navigation commands (`NEXT`, `PREVIOUS`) separate from physical Left/Right key mappings. Do not spread RTL conditionals across unrelated UI code.

### 8.4 Viewer architecture

Do not create a completely separate comic viewer if the existing `ImageViewer` can be generalized.

The target scene can contain one or two page/media items. Shared behavior should include:

- fit;
- 100%;
- zoom;
- pan;
- rotate where sensible;
- fullscreen.

In Double Page mode, `0` should normally fit the complete spread.

## 9. Settings and UI integration

Work item: #9

Use `QSettings` only for non-sensitive preferences.

Persist:

- window geometry/state;
- thumbnail sidebar visibility;
- Single/Double Page mode;
- LTR/RTL direction;
- first-page-cover preference.

Never persist:

- archive passwords;
- image bytes;
- private archive contents.

Suggested menus:

```text
File
  Open Archive
  Exit

View
  Single Page
  Double Page
  Thumbnail Sidebar
  Fit
  Actual Size
  Fullscreen

Reading
  Left to Right
  Right to Left
  First Page Is Cover

Help
  Keyboard Shortcuts
  About ArchiveLens
```

Update open-dialog and drag/drop support for:

- `.zip`;
- `.cbz`;
- `.7z`;
- `.rar`;
- `.cbr`.

## 10. Windows installer

Work item: #10

Keep the existing portable build and add:

```text
ArchiveLens-1.1.0-windows-x64.zip
ArchiveLens-1.1.0-setup-x64.exe
```

Recommended installer technology: Inno Setup.

Recommended install location:

```text
%LocalAppData%\Programs\ArchiveLens
```

This keeps normal installation per-user and usually avoids elevation.

Installer tasks:

- Start Menu shortcut: on by default;
- Desktop shortcut: optional;
- register ArchiveLens as an Open With application;
- do not silently hijack `.zip`, `.rar`, or `.7z` defaults;
- optional/explicit `.cbz` and `.cbr` association where practical;
- clean uninstall of ArchiveLens-owned files and registry entries only.

The installed application must include any backend needed for RAR/CBR use.

CI should support silent install, packaged self-test, and silent uninstall verification.

## 11. Security and resource limits

v1.0 safeguards remain mandatory.

v1.1 should additionally consider centralized limits for:

- maximum archive entry count;
- maximum uncompressed entry size;
- maximum compression ratio;
- maximum image pixels;
- full-image cache bytes;
- thumbnail cache bytes;
- animated-media bytes/resources.

No new feature may introduce:

- an unbounded worker queue;
- an unbounded decoded-media cache;
- unlimited thumbnail enumeration/decode work;
- password logging;
- source archive modification.

Performance/regression work is tracked in #12.

## 12. Dependency and license decisions

Work item: #13

Before release, record the chosen ZIP AES, 7Z and RAR/CBR backends with:

- package/library name;
- supported version/range;
- license;
- whether native binaries are used;
- redistribution requirements;
- supported/unsupported compression/encryption cases;
- packaging implications.

Feed these decisions into:

- `pyproject.toml`;
- build constraints;
- PyInstaller spec;
- `prepare_licenses.py`;
- `THIRD_PARTY_NOTICES.md`;
- release manifests/source bundles where required.

### Thumbnail behavior

- lazy loading;
- visible-range priority;
- rapid scrolling;

### Concurrency/resource behavior

- rapid Next/Previous;

### Packaging

- portable package verification;
- installer build;

## 14. Manual Windows QA

Work item: #14

Before tagging v1.1.0, perform a small manual QA pass on Windows 10/11 because offscreen Qt tests cannot fully validate Explorer integration, real DPI/multi-monitor behavior, drag/drop, installer UX or animation smoothness.

The pass should include:

- clean installer install and uninstall;
- portable build launch outside the source tree;
- Explorer drag/drop and Open With;
- representative ZIP/CBZ/7Z/RAR/CBR archives;
- password flows;
- GIF playback;
- thumbnail scrolling;
- double-page LTR/RTL;
- fullscreen/zoom/pan;
- multi-monitor/high-DPI movement;
- closing during active loading;
- checking that no extracted image folder/password persistence remains.

## 16. Codex handoff protocol

When Codex starts implementation work, give it **one target issue at a time**.

For each issue, Codex should:

1. Read this document, the target issue, relevant current source files and relevant tests before editing.
2. Respect stated dependencies; do not implement a downstream issue by bypassing unfinished architecture work.
3. Keep changes scoped to the issue plus the minimum prerequisite/refactor required.
4. Preserve v1.0 local-only, read-only and bounded-resource guarantees.
5. Add or update tests with the implementation.
6. Run focused tests during iteration.
7. Before completion, run the full pytest and Ruff checks expected by the repository.
8. Update documentation only when the issue changes user-visible or developer-visible behavior.
9. Reference the issue number in commits/PRs.
10. Do not silently weaken resource guards, password redaction, archive immutability or release verification.
11. If backend licensing/redistribution is unresolved, produce a documented spike/result instead of assuming shipping rights.
12. Keep the repository runnable at the end of every issue.

Suggested prompt when starting with Codex:

> Implement ArchiveLens issue #N. First read `docs/V1.1_PLAN.md`, issue #N, the current repository architecture, and relevant tests. Work only on that issue and its documented prerequisites. Preserve existing v1.0 behavior unless the issue explicitly changes it. Add tests, run focused tests during development, then run the repository's full pytest and Ruff checks. Do not weaken archive immutability, resource limits, password redaction, or packaged-release verification. Summarize changed files, tests run, and any remaining risk when finished.

## 17. v1.1 definition of done

v1.1.0 is ready only when a Windows user can:

1. Download either the portable ZIP or setup EXE.
2. Install with a normal Windows setup wizard without installing Python.
3. Open ZIP, CBZ, 7Z, RAR and CBR archives supported by the documented backends.
4. Enter archive passwords when required.
5. View supported static images and animated GIFs.
6. Toggle a lazy thumbnail sidebar and jump to a page.
7. Use single- or double-page comic viewing.
8. Switch between LTR and RTL reading.
9. Close/uninstall without ArchiveLens modifying the original archives or leaving extracted image folders behind.

Release engineering must also pass:

- source tests;
- Ruff checks;
- portable package verification;
- installer verification;
- packaged self-test;
- license/notice verification;
- manual Windows QA;
- final clean-checkout CI run.

## 18. Explicitly out of scope for v1.1

Do not expand v1.1 to include:

- nested archives;
- archive editing;
- deleting/renaming archive members;
- continuous vertical comic scrolling;
- bookmarks;
- cloud sync;
- OCR;
- slideshow;
- HEIC/AVIF;
- macOS installer;
- Linux AppImage/installer;
- auto-update;
- Microsoft Store packaging.

Those belong in v1.2+ unless a small prerequisite is strictly necessary for a v1.1 item.

## 19. Release tag gate

Work item: #15

Do not create `v1.1.0` until:

- all required v1.1 issues are closed or explicitly deferred with rationale;
- version metadata is consistently `1.1.0`;
- README/README.zh-TW/CHANGELOG match tested behavior;
- portable and installer artifacts both verify;
- SHA-256/build metadata are generated and checked;
- third-party notices and redistribution obligations are complete;
- manual QA has no open blocker;
- the final CI run from a clean checkout is green.

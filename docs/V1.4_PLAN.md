# ArchiveLens v1.4 Development Plan

Target version: **1.4.0**

This document carries forward the advanced-reader and lightweight-library work that was originally planned for v1.3. ArchiveLens v1.3 is now reserved for the macOS and cross-platform foundation. v1.4 should therefore improve **how supported content is read and managed** after v1.3 establishes supported Windows x64 and macOS Apple Silicon builds.

## 1. Release goal

ArchiveLens v1.4 should evolve into an advanced local comic/image reader with a lightweight library while preserving the project’s core identity:

- local-first;
- read-only sources;
- no account requirement;
- no telemetry/cloud dependency;
- bounded memory/work queues;
- explicit, auditable native dependencies;
- fast direct-open workflow even when the library is unused;
- feature parity across supported Windows x64 and macOS arm64 builds unless an issue explicitly documents a platform limitation.

The primary v1.4 scope is:

1. Continuous vertical reading and Webtoon mode with virtualized/lazy page loading.
2. A lightweight local library/bookshelf for user-selected folders.
3. Series grouping based primarily on folder structure and explicit local metadata rather than mandatory online services.
4. Cover/thumbnail caching with strict disk/resource bounds.
5. A reusable image-effect pipeline plus magnifier/loupe.
6. A command/input abstraction with user-configurable keyboard and mouse bindings.
7. Touch/gesture interaction improvements where practical on supported platforms.
8. Slideshow/auto-advance as a small reader feature.
9. Optional nested-archive support limited to depth 1 if the security/performance spike passes.

## 2. v1.3 baseline that must be preserved

v1.4 assumes v1.3 successfully provides and regression-protects:

- the v1.2 `ContentProvider` or equivalent content-source abstraction;
- ZIP/CBZ, 7Z, RAR/CBR providers on supported platforms;
- folder content provider with safe recursive discovery;
- PDF content provider;
- decoder registry and v1.2 image formats;
- resume/recent history/bookmarks;
- Fit Page/Spread, Fit Width, Fit Height, Actual Size;
- non-destructive border trim;
- single/double page, cover handling, LTR/RTL;
- thumbnail sidebar and animated GIF;
- source immutability and session-only credentials;
- bounded caches/queues and stale-result protection;
- Windows x64 portable/installer packaging;
- macOS arm64 `.app`/DMG packaging;
- platform-neutral native-backend abstractions;
- macOS Finder document integration, Retina/high-DPI qualification, signing/notarization release path, and CI verification.

v1.4 must not bypass or duplicate these abstractions or reintroduce platform-specific reader logic unnecessarily.

## 3. Continuous and Webtoon reading architecture

### 3.1 Virtualization is mandatory

Do not implement continuous mode by creating hundreds of full-resolution widgets/pixmaps or by stitching a full book into one giant image.

Use an explicit model such as:

```text
ContinuousReader
├── PageLayoutModel
├── VisibleRange
├── PrefetchRange
├── Render/Decode Scheduler
└── Eviction Policy
```

Only visible pages plus a bounded look-ahead/look-behind range should be decoded/rendered at useful resolution.

### 3.2 Reading modes

v1.4 should support:

- Single Page;
- Double Page;
- Continuous Vertical;
- Webtoon / near-zero-gap vertical mode.

Requirements:

- archive, folder, and PDF content sources where provider behavior permits;
- bounded decoded/rendered page count and memory;
- generation/stale-result protection;
- scroll-position restoration;
- thumbnail/bookmark/history integration;
- explicit zoom/fit behavior;
- resize/high-DPI recalculation without losing logical reading position;
- long chapters remain usable without eager full decode;
- supported Windows/macOS builds share the same reader model.

Webtoon mode may use a smaller/zero inter-page gap and Fit Width as its natural default while still respecting render-pixel limits.

## 4. Lightweight library

### 4.1 Product boundary

The library is optional. Direct-open workflows remain first-class; users must not be required to import content before reading.

### 4.2 Library roots and discovery

Users can add one or more local folders as library roots. Reuse the common content-source detection rules to discover supported archive books, PDFs, and image-folder books.

### 4.3 Local database

Use a versioned local database, preferably SQLite, for data that is larger/more relational than QSettings.

Suggested logical entities:

```text
library_roots
books
series
local/user metadata as needed
reading_state reference
bookmarks reference
cover_cache metadata
```

Do not store passwords or decrypted content.

### 4.4 Library views

Minimum useful UI:

- Continue Reading;
- Recently Opened;
- Recently Added;
- All Books;
- Folders / Series.

Book tiles/cards should show useful information such as cover, title, progress, and unread/finished state without becoming a metadata-heavy media server.

## 5. Series grouping

Use a deterministic local-first strategy:

- folder structure can define series;
- contained archive/PDF/folder books become volumes/items;
- natural ordering is used within a series;
- users may correct/override title/grouping locally if a minimal metadata editor is included.

Do not require AniList, MyAnimeList, Bangumi, scraping, or cloud metadata services.

## 6. Cover and thumbnail disk cache

The library cache must remain bounded and rebuildable.

Requirements:

- separate cache from source files;
- source identity/version validation;
- configurable/fixed disk budget;
- LRU/age-based eviction;
- safe recovery if cache is deleted/corrupted;
- no decrypted source pages retained for encrypted books by default;
- cache format/version migration or rebuild strategy;
- identical privacy behavior across Windows and macOS.

For encrypted sources, prefer a generic placeholder or session-generated non-persistent cover unless a later privacy review explicitly approves persistence.

## 7. Image-effect pipeline and magnifier

Introduce a reusable, non-destructive render effect pipeline rather than UI-specific pixel mutations.

Initial effects:

- brightness;
- contrast;
- gamma;
- grayscale;
- invert;
- optional saturation/sharpen only if bounded and well-tested.

Requirements:

- source bytes/images remain unchanged;
- effects reset quickly;
- predictable interaction with trim, rotation, fit, and zoom;
- bounded processing without unnecessary full-resolution duplication;
- expensive transforms do not block the UI thread;
- common behavior across supported platforms.

Add a magnifier/loupe with practical 2x/3x/4x levels that uses the current rendered page, works with trim/effects, and behaves correctly in single/double/continuous modes.

AI upscaling, descreening, colorization, OCR, and mandatory GPU-specific dependencies remain out of scope.

## 8. Command and input abstraction

Refactor reader actions behind named logical commands, for example:

```text
NEXT_PAGE
PREVIOUS_PAGE
NEXT_BOOK
PREVIOUS_BOOK
FIT_PAGE
FIT_WIDTH
FIT_HEIGHT
ACTUAL_SIZE
TOGGLE_FULLSCREEN
TOGGLE_BOOKMARK
TOGGLE_THUMBNAILS
TOGGLE_MAGNIFIER
```

Keyboard, mouse, touch/trackpad, and future controllers should dispatch commands rather than implementing separate reader behavior.

v1.4 target:

- keyboard shortcut customization;
- mouse button/wheel action customization where practical;
- platform-appropriate defaults (Ctrl vs Command through Qt standard-key behavior where applicable);
- conflict detection;
- restore defaults;
- invalid/old settings fail safely.

Logical NEXT/PREVIOUS semantics remain separate from physical left/right so RTL behavior stays correct.

## 9. Touch/gesture interaction

Where Qt/platform support is reliable, improve touch/gesture use without redesigning the application.

Potential scope:

- tap zones for next/previous;
- pinch zoom;
- drag/pan;
- vertical continuous scrolling;
- fullscreen-friendly controls;
- macOS trackpad behavior where it maps naturally to Qt gestures/scroll events.

Do not make specialized hardware behavior a release blocker when test coverage is insufficient; manual QA must document actual tested devices.

## 10. Slideshow / auto-advance

Add an optional auto-advance feature with configurable interval, pause/resume, predictable end behavior, optional explicit looping, and guaranteed timer cleanup on source close/application shutdown.

## 11. Nested archive depth 1

Nested archives remain optional and safety-gated.

Initial maximum depth: **1 nested archive level**.

Requirements:

- no unbounded recursion;
- combined compressed/uncompressed resource accounting;
- nested-entry size limits;
- credential flow for encrypted outer/inner archives without persistence/logging;
- no user-visible full extraction;
- bounded inner-archive strategy;
- nested source identity in cache/page keys;
- corrupt/unsupported inner archives fail recoverably;
- solid-archive costs respected;
- supported Windows/macOS backend combinations documented explicitly.

A documented defer is preferable to weakening ArchiveLens safeguards.

## 12. Library scanning and resource safety

Central safeguards:

- maximum concurrent scans;
- bounded work queue;
- cancellation/generation handling;
- root/path loop protection;
- database transaction boundaries;
- source sniffing without full decode during discovery;
- separate bounded cover-generation queue;
- bounded disk cache;
- no automatic network traversal;
- clean behavior when external/removable drives disappear.

## 13. Privacy and security

Preserve existing principles:

- no telemetry;
- no mandatory cloud/account;
- no persistent passwords;
- no source modification;
- no persistent decrypted cache by default;
- no metadata upload;
- no silent network access.

## 14. Test matrix

### Continuous/Webtoon

- 10/100/500+ page sources;
- archive/folder/PDF;
- visible-range loading;
- bounded prefetch and eviction;
- fast scrolling and source switch;
- resume scroll position;
- resize/high-DPI;
- bookmarks/thumbnails integration;
- no giant stitched image;
- Windows/macOS parity fixtures where practical.

### Library

- add/remove root;
- scan archives/PDF/folders;
- Unicode/long paths;
- duplicate/moved books;
- removable/missing root;
- database migration and interrupted-scan recovery;
- recent/continue/progress views;
- series grouping/order;
- bounded cover queue/cache;
- encrypted-source privacy behavior.

### Effects/magnifier

- each effect independently and reset;
- combinations within defined limits;
- trim/rotation/zoom interaction;
- continuous mode;
- magnifier at boundaries;
- no source mutation;
- no runaway memory duplication.

### Input/gesture

- default shortcuts regression;
- custom shortcut round-trip and conflicts;
- RTL logical navigation;
- mouse wheel/buttons;
- touch/trackpad where testable;
- invalid settings fallback.

### Nested archive

- one nested level;
- rejection beyond depth limit;
- encrypted outer/inner cases as supported;
- corrupt/oversized inner archive;
- resource accounting;
- cache identity;
- solid-archive behavior;
- platform/backend matrix.

### Regression

All v1.3 Windows/macOS content sources and formats, resume/history/bookmarks, PDF, folder recursion, trim/fit modes, credentials, thumbnails, animation, packaging, signing/notarization validation, and source immutability.

## 15. Manual QA

Before v1.4.0, manually verify on supported Windows x64 and macOS arm64 builds:

- continuous/Webtoon on long real content;
- multi-monitor/high-DPI/Retina behavior;
- library scan on small and large folders;
- external/removable drive disappearance;
- cover cache growth/eviction;
- encrypted-source privacy;
- effects/magnifier on large pages;
- keyboard/mouse customization;
- platform-specific touch/trackpad behavior if shipped;
- nested archive cases if shipped;
- clean upgrade from v1.3 data/settings;
- Windows installer/portable and macOS app/DMG builds.

## 16. Explicitly deferred from v1.4

Unless a minimal prerequisite is unavoidable, defer:

- cloud sync;
- OPDS/SMB/WebDAV/SFTP/S3 remote sources;
- online manga trackers/metadata services;
- AI upscale/descreen/colorization;
- OCR;
- annotation/editing;
- EPUB unless separately planned;
- plugin marketplace;
- user accounts;
- Linux packaged releases;
- unlimited nested archive recursion.

## 18. Codex handoff protocol

For each v1.4 issue, Codex should:

1. Read this plan, `docs/V1.3_PLAN.md`, `docs/V1.2_PLAN.md`, the target issue, and relevant current code/tests.
2. Work on one issue plus only documented prerequisites.
3. Preserve direct-open workflows and keep the library optional.
4. Preserve read-only/local-only behavior, ephemeral credentials, bounded resources, stale-result protection, and source immutability.
5. Preserve supported Windows x64 and macOS arm64 behavior; do not introduce unnecessary platform-specific reader forks.
6. Avoid eager decode/render of complete long books or complete libraries.
7. Add deterministic resource/cancellation tests for background work.
8. Run focused tests, then full pytest/Ruff/package checks appropriate to the issue.
9. Keep persistent cache/database formats versioned and recoverable.
10. Do not add silent network behavior.
11. Leave the repository runnable after every issue.

Suggested starting prompt:

> Implement ArchiveLens v1.4 issue #N. First read `docs/V1.4_PLAN.md`, `docs/V1.3_PLAN.md`, `docs/V1.2_PLAN.md`, issue #N, and the relevant current architecture/tests. Work only on that issue and its documented prerequisites. Preserve local-only/read-only behavior, bounded caches/queues, credential redaction, source immutability, direct-open workflows, and Windows x64/macOS arm64 packaged compatibility. Add tests, run focused checks, then run the full checks required by the issue.

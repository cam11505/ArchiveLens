# ArchiveLens v1.2.0 release-candidate QA

Status date: **2026-09-16**

Feature/hardening baseline: `b8917f0` on `codex/v1.2`. RC verification then found
that deeply nested QtPdf attribution paths could exceed an installer destination's
path budget. The final candidate content-addresses those paths and retains their
upstream locations in `PATHS.json`, then rebuilds every artifact from the exact
post-fix commit before tag.

## Tested environment

- Windows 11 x64, build 22631, AMD64.
- One physical ASUS PA279 display exposed to Qt at 2560 x 1440, device pixel ratio 1.5.
- Python 3.12.14, PySide6/Qt 6.11.2, Pillow 12.3.0, PyInstaller 6.22.3,
  Inno Setup 6.7.3.
- Windows GitHub CI additionally runs the clean-checkout production installer test;
  Linux CI covers source-level portability only, not a supported packaged release.

## Explicit deferrals and coverage limits

- HEIC/HEIF and JPEG XL are not shipped. Their evaluated Windows backends failed the
  license, pre-decode resource or package-cost gate; this is a documented product
  limitation, not an incomplete shipped feature.
- Windows 10 hardware, a second physical monitor/DPI transition, and physical Explorer
  Open With interaction were not available on this host. They are explicitly deferred
  as non-blocking environment coverage. The same code paths are covered by Qt resize/DPI,
  registry-policy, isolated installer and clean Windows CI checks; no pass is claimed for
  those physical scenarios.
- The existing user ArchiveLens v1.1.0 installation was preserved. Local installer QA
  used a separate AppId with the exact portable payload. The production AppId/Open With
  lifecycle must pass the clean GitHub Windows runner before tagging.
- Native Windows app control was unavailable in this Codex session. Visual inspection
  used the screenshot produced by the real packaged executable after its interaction
  self-test; this is not represented as free-form human mouse/keyboard testing.

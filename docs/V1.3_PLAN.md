# ArchiveLens v1.3 Development Plan

Target version: **1.3.0**

This document defines the v1.3 work after ArchiveLens v1.2.0. v1.2 expands what ArchiveLens can read: archives, recursive image folders, additional image codecs, and PDF, with resume/history/bookmarks and stronger reader fit/crop behavior. v1.3 should focus on **how content is read and managed** without turning ArchiveLens into a cloud-centric media platform.

## 1. Release goal

ArchiveLens v1.3 should evolve into an advanced local comic/image reader with a lightweight library while preserving the project’s core identity:

- local-first;
- read-only sources;
- no account requirement;
- no telemetry/cloud dependency;
- bounded memory/work queues;
- explicit, auditable native dependencies;
- fast direct-open workflow even when the library is unused.

The primary v1.3 scope is:

1. Continuous vertical reading and Webtoon mode with virtualized/lazy page loading.
2. A lightweight local library/bookshelf for user-selected folders.
3. Series grouping based primarily on folder structure and explicit local metadata rather than mandatory online services.
4. Cover/thumbnail caching with strict disk/resource bounds.
5. A reusable image-effect pipeline plus magnifier/loupe.
6. A command/input abstraction with user-configurable keyboard and mouse bindings.
7. Touch interaction improvements where practical on Windows.
8. Slideshow/auto-advance as a small reader feature.
9. Optional nested-archive support limited to a deliberately small depth (initial target: depth 1) if the security/performance spike passes.

## 2. v1.2 baseline that must be preserved

v1.3 assumes v1.2 successfully provides and regression-protects:

- `ContentProvider` or equivalent content-source abstraction;
- existing `ArchiveProvider` implementations for ZIP/CBZ, 7Z, RAR/CBR;
- folder content provider with safe recursive discovery;
- PDF content provider;
- decoder registry and v1.2 image formats;
- resume/recent history/bookmarks;
- Fit Page/Spread, Fit Width, Fit Height, Actual Size;
- non-destructive border trim;
- single/double page, cover handling, LTR/RTL;
- thumbnail sidebar;
- animated GIF;
- source immutability;
- session-only credentials;
- bounded caches/queues;
- Windows portable + installer packaging and verification.

v1.3 must not bypass or duplicate these abstractions.

## 3. Continuous and Webtoon reading architecture

### 3.1 Do not implement continuous mode as “load every page”

The current page/spread model should not be extended by creating hundreds of full-resolution widgets/pixmaps at once.

Continuous reading needs an explicit virtualization model such as:

```text
ContinuousReader
├── PageLayoutModel
├── VisibleRange
├── PrefetchRange
├── Render/Decode Scheduler
└── Eviction Policy
```

Only visible pages plus a bounded look-ahead/look-behind range should be decoded/rendered at useful resolution.

### 3.2 Reading modes

v1.3 should support:

- Single Page;
- Double Page;
- Continuous Vertical;
- Webtoon / near-zero-gap vertical mode.

Continuous mode requirements:

- archive, folder, and PDF sources where backend behavior permits;
- bounded decoded/rendered page count and memory;
- generation/stale-result protection;
- scroll-position restoration;
- thumbnail/bookmark/history integration;
- zoom/fit behavior defined explicitly;
- resize/high-DPI recalculation without losing the logical reading position;
- long chapters (hundreds/thousands of pages) remain usable without eager full decode.

### 3.3 Webtoon specifics

Webtoon mode may use a smaller/zero inter-page gap and Fit Width as its natural default. It must still respect maximum render pixel limits and avoid constructing one giant stitched image.

## 4. Lightweight library

### 4.1 Product boundary

The library is optional. Direct-open workflows remain first-class.

ArchiveLens should not require users to import everything into a database before reading.

### 4.2 Library sources

Users can add one or more local folders as library roots. The library scanner discovers supported:

- archive books;
- PDFs;
- image folders according to explicit rules;
- supported content types added by later versions.

The scanner must reuse v1.2 source-detection rules rather than implement a separate format stack.

### 4.3 Local database

Use a versioned local database, preferably SQLite, for data that is larger/more relational than QSettings.

Suggested logical entities:

```text
library_roots
books
series
authored/user metadata as needed
reading_state reference
bookmarks reference
cover_cache metadata
```

Do not store passwords/decrypted content.

### 4.4 Library views

Minimum useful UI:

- Continue Reading;
- Recently Opened;
- Recently Added;
- All Books;
- Folders / Series.

Book tiles/cards should show only useful information such as cover, title, progress, and unread/finished state. Avoid turning v1.3 into a metadata-heavy media server.

## 5. Series grouping

The initial grouping strategy should be deterministic and local-first.

Preferred rule:

- library folder structure can define series;
- contained archive/PDF/folder books become volumes/items;
- natural ordering is used within a series;
- users may correct/override title/grouping locally if a minimal metadata editor is included.

Do not require AniList, MyAnimeList, Bangumi, scraping, or cloud metadata services in v1.3.

Example:

```text
LibraryRoot/
└── Example Series/
    ├── Vol 01.cbz
    ├── Vol 02.cbz
    └── Vol 03.pdf
```

becomes one local series containing three books.

## 6. Cover and thumbnail disk cache

The library needs persistent visual metadata, but the cache must remain bounded and rebuildable.

Requirements:

- separate cache from source files;
- source identity/version validation;
- configurable/fixed disk budget;
- LRU/age-based eviction;
- safe failure if cache is deleted/corrupted;
- no decrypted source pages retained for encrypted books unless the design is explicitly reviewed; default should avoid persistent decrypted-page caching;
- cache format/version migration or rebuild strategy.

For encrypted sources, prefer a generic placeholder or session-generated non-persistent cover unless a privacy review explicitly approves persistence.

## 7. Image-effect pipeline

Introduce a reusable, non-destructive render effect pipeline rather than UI-specific pixel mutations.

Initial effects may include:

- brightness;
- contrast;
- gamma;
- grayscale;
- invert;
- optional saturation/sharpen if implementation remains bounded and well-tested.

Requirements:

- source bytes/images remain unchanged;
- effects can be reset quickly;
- effects work predictably with trim, rotation, fit, and zoom;
- processing is bounded and does not duplicate full-resolution images unnecessarily;
- effect settings may be global and optionally per-source if the persistence model remains simple;
- expensive transforms must not block the UI thread.

Advanced AI upscaling, descreening, colorization, OCR, and GPU-heavy enhancement are explicitly out of v1.3 scope.

## 8. Magnifier / loupe

Add a lightweight magnifier suitable for small text/detail inspection.

Requirements:

- keyboard/mouse invocation;
- configurable or fixed magnification levels such as 2x/3x/4x;
- operates on the current rendered page without forcing an unbounded re-decode;
- works with image effects and trim;
- clean behavior in single/double/continuous modes;
- no permanent source modification.

## 9. Command and input abstraction

### 9.1 Commands, not scattered key checks

Refactor reader actions behind named commands, for example:

```text
NEXT_PAGE
PREVIOUS_PAGE
NEXT_BOOK
PREVIOUS_BOOK
FIT_PAGE
FIT_WIDTH
FIT_HEIGHT
ACTUAL_SIZE
TOGGLE_FULLSCREEN
TOGGLE_BOOKMARK
TOGGLE_THUMBNAILS
TOGGLE_MAGNIFIER
```

Keyboard, mouse, touch, and future controllers should dispatch commands rather than each implementing reader logic separately.

### 9.2 User-configurable bindings

v1.3 target:

- keyboard shortcut customization;
- mouse button/wheel action customization where practical;
- conflict detection;
- restore defaults;
- import/export may be deferred unless trivial;
- invalid/old settings fail safely.

Logical NEXT/PREVIOUS semantics must remain separate from physical left/right so RTL behavior stays correct.

## 10. Touch interaction

Where supported by Qt/Windows, improve touch use without redesigning the entire UI.

Potential v1.3 scope:

- tap zones for next/previous;
- pinch zoom;
- drag/pan;
- vertical continuous scrolling;
- fullscreen-friendly controls.

Touch must dispatch the same command/reader abstractions where applicable.

Do not make touch a release blocker if hardware/CI coverage is insufficient; manual QA must clearly document what was tested.

## 11. Slideshow / auto-advance

Add a small optional auto-advance feature:

- user-selectable interval;
- pause/resume;
- stops safely at end or optionally loops only with explicit setting;
- works only in modes where behavior is well-defined;
- user navigation resets/pauses predictably;
- no background timer survives source close/application shutdown.

This feature is lower priority than continuous mode, library, effects, and input abstraction.

## 12. Nested archive depth 1

Nested archives are optional v1.3 scope gated by a security/performance spike.

Target example:

```text
outer.zip
└── chapter01.cbz
    ├── 001.jpg
    └── 002.jpg
```

Initial maximum depth: **1 nested archive level**.

Requirements:

- no unbounded recursion;
- combined compressed/uncompressed resource accounting;
- nested-entry size limits;
- credential flow defined when outer/inner archives are encrypted;
- no writing/extracting full nested archives to user-visible directories;
- avoid duplicating entire large inner archives in memory when a safer bounded strategy exists;
- natural page identity and cache keys include nested source identity;
- corrupt/unsupported inner archives fail recoverably;
- solid archive cost is respected.

If a safe/maintainable backend strategy cannot satisfy these constraints, nested archives should be deferred rather than weakening ArchiveLens safeguards.

## 13. Library scanning and resource safety

Library scanning can become the largest new background workload in v1.3.

Central safeguards should include:

- maximum concurrent scans;
- bounded work queue;
- cancellation/generation handling;
- root/path loop protection;
- database transaction boundaries;
- source type sniffing that avoids fully decoding every book during discovery;
- cover generation queue separate from core scan;
- bounded disk cache;
- no automatic network traversal;
- clean behavior when external/removable drives disappear.

## 14. Privacy and security

Preserve existing principles:

- no telemetry;
- no mandatory cloud/account;
- no persistent passwords;
- no source modification;
- no persistent decrypted cache by default;
- no metadata upload;
- no silent network access.

If any future online metadata or remote-source feature is considered, it belongs in a later explicitly reviewed release.

## 15. Test matrix

### Continuous/Webtoon

- 10/100/500+ page synthetic sources;
- archive/folder/PDF;
- visible-range loading;
- bounded prefetch;
- eviction under memory budget;
- fast scrolling;
- source switch mid-load;
- resume scroll position;
- resize/high-DPI;
- bookmarks/thumbnails integration;
- no giant stitched image.

### Library

- add/remove root;
- scan archives/PDF/folders;
- Unicode/long paths;
- duplicate/moved books;
- removable/missing root;
- database migration;
- interrupted scan recovery;
- recent/continue/progress views;
- series grouping/order;
- bounded cover queue/cache;
- encrypted-source privacy behavior.

### Effects/magnifier

- each effect independently;
- reset;
- combinations within defined limits;
- trim/rotation/zoom interaction;
- continuous mode;
- magnifier at page edges;
- no source mutation;
- no runaway memory duplication.

### Input

- default shortcuts regression;
- custom shortcut round-trip;
- conflict detection;
- RTL logical navigation;
- mouse wheel/buttons;
- touch where testable;
- invalid settings fallback.

### Nested archive spike/implementation

- one nested level;
- depth rejection beyond limit;
- encrypted outer/inner cases as supported;
- corrupt inner archive;
- resource accounting;

### Regression

## 16. Manual Windows QA

Before v1.3.0:

- continuous/Webtoon on long real content;
- smooth scrolling on integrated/discrete GPU representative systems where possible;
- multi-monitor/high-DPI;
- library scan on small and large folders;
- external/removable drive disappearance;
- cover cache growth/eviction;
- encrypted-source privacy behavior;
- image effects on large pages;
- magnifier interaction;
- keyboard/mouse customization;
- touch on at least one compatible device if touch is shipped;
- nested archive cases if shipped;
- clean upgrade from v1.2 data/settings;
- portable and installer builds.

## 17. Explicitly deferred from v1.3

Unless a minimal prerequisite is unavoidable, defer:

- cloud sync;
- OPDS/SMB/WebDAV/SFTP/S3 remote sources;
- online manga trackers/metadata services;
- AI upscale/descreen/colorization;
- OCR;
- annotation/editing;
- EPUB if not already separately planned;
- plugin marketplace;
- user accounts;
- macOS/Linux packaged releases;
- unlimited nested archive recursion.

## 18. Recommended implementation / Codex order

Recommended order:

1. v1.3 parent/tracking issue and this plan.
2. Continuous/Webtoon virtualized reader architecture and bounded loading.
3. Library database/scanner foundation.
4. Library UI, series grouping, continue/recent views, and bounded cover cache.
5. Image-effect pipeline and magnifier.
6. Command/input abstraction and configurable keyboard/mouse bindings.
7. Touch/slideshow interaction enhancements.
8. Nested archive depth-1 spike and implementation only if the spike passes.
9. CI/resource/security/migration/release hardening and manual QA.

The library and continuous-reader work may proceed in parallel after v1.2 abstractions are stable, but neither may bypass the common content-provider, reading-state, decoder, cache, and credential models.

## 19. Codex handoff protocol

For each v1.3 issue, Codex should:

1. Read this plan, `docs/V1.2_PLAN.md`, the target issue, and relevant current code/tests.
2. Work on one issue plus only its documented prerequisites.
3. Preserve direct-open workflows; do not make the library mandatory.
4. Preserve read-only source handling, local-only behavior, ephemeral credentials, bounded resources, and stale-result protection.
5. Avoid eager decode/render of complete long books or complete libraries.
6. Add deterministic resource/cancellation tests for background work.
7. Run focused tests, then full pytest/Ruff/package checks appropriate to the issue.
8. Keep persistent cache/database formats versioned and recoverable.
9. Do not add silent network behavior.
10. Leave the repository runnable after every issue.

Suggested starting prompt:

> Implement ArchiveLens v1.3 issue #N. First read `docs/V1.3_PLAN.md`, `docs/V1.2_PLAN.md`, issue #N, and the relevant current architecture/tests. Work only on that issue and its documented prerequisites. Preserve local-only/read-only behavior, bounded caches/queues, credential redaction, source immutability, direct-open workflows, and Windows packaged compatibility. Add tests, run focused checks, then run the full checks required by the issue.

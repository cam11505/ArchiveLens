> Issue #42 environment decision (2026-09-16): macOS uses the GitHub-hosted
> `macos-15` Apple Silicon arm64 runner. Pinning the image avoids
> `macos-latest` drift. Linux uses `ubuntu-latest` x64; both run source and
> minimal PyInstaller frozen diagnostics.

Target version: **1.3.0**

Original compatibility-spike baseline:

```text
tag: v1.2.0
commit: af0c01b46041f26ce19a978237970d866eaf017c
```

The initial #42 spike and PR #52 retain this exact historical baseline. After the
v1.2 maintenance work completed, the immutable implementation baseline for #43–#51
became:

```text
tag: v1.2.2
commit: bb0197b0291707287517ba8bdfc3a10ce1ad1149
```

Issue #42 completed the v1.2.2 delta revalidation, #43 established the narrow
platform seams and unified source-open boundary, #44 recorded a cross-platform RAR
**Go** decision, and #45 completed macOS arm64 shipped-codec/QtPdf qualification.
The current implementation entry point is #46. Every later v1.3 branch, test result,
and compatibility claim must identify the v1.2.2 implementation baseline; do not use
an unspecified post-v1.2 state.

ArchiveLens v1.3 is the **macOS & Cross-platform Foundation** release. Official packaged targets remain:

- Windows x64;
- macOS Apple Silicon (`arm64`).

Linux packaged releases are deferred. Existing Ubuntu/Linux source compatibility and CI are an established contract and must remain green.

## 1. Release goal and boundaries

v1.3 ports and productizes the shipped v1.2 feature set without redesigning the reader or adding the advanced-reader/library scope reserved for v1.4.

Primary work:

1. **Completed (#42):** macOS arm64 + Linux compatibility/backend spike and v1.2.2 delta revalidation.
2. **Completed (#42):** minimal frozen-runtime diagnostics on both platforms.
3. **Completed (#43):** narrow Windows/platform runtime seams and unified source-open boundary.
4. **Completed (#44 — Go):** platform-neutral RAR/CBR backend with qualified macOS arm64 and Linux runtime paths.
5. **Completed (#45):** shipped v1.2.2 codec/PDF matrix qualification on macOS arm64.
6. **Current (#46):** build a self-contained macOS arm64 `.app`, then add Finder integration, Retina qualification, signing, notarization, and DMG packaging.
7. Introduce a platform-neutral build-info/manifest contract with platform-specific verifiers.
8. Preserve the Windows x64 release path and Ubuntu source CI throughout.

This release does **not** add direct single-image sources, a second media pipeline, configurable inputs, Webtoon/continuous reading, or a library.

## 2. v1.2 parity baseline

The immutable baseline provides and regression-protects:

- content/archive provider registries for ZIP/CBZ, 7Z, RAR/CBR, folders, and PDFs;
- safe recursive folders and QtPdf/password-PDF reading;
- `DecoderRegistry` and the shipped raster matrix;
- resume/history/bookmarks, fit modes, Actual Size, and non-destructive trim;
- single/double page, cover handling, LTR/RTL, thumbnails, and animated GIF;
- byte-bounded caches/work, stale-result rejection, and source-switch cancellation;
- source immutability, local-only operation, and session-only credentials;
- Windows x64 portable/installer packaging and verification;
- Windows and Ubuntu source/test CI.

Required v1.2 raster parity is:

- JPEG, PNG, WebP, BMP, and GIF;
- TIFF;
- AVIF;
- JPEG 2000 (`.jp2`, `.j2k`, `.j2c`).

HEIC/HEIF and JPEG XL/JXL were evaluated and **not shipped in v1.2**. They are not parity requirements or v1.3 release blockers. Reconsidering either requires separately approved backend, license, packaging, and resource evidence.

## 3. Protected architecture

Preserve these boundaries and contracts unless a measured blocker proves a narrow change necessary:

- `ContentProvider` / `ContentProviderRegistry`;
- `ArchiveProvider` / `ArchiveProviderRegistry`;
- `PageDescriptor` / `SourceIdentity`;
- `DecoderRegistry`;
- `ImageWorker` ownership, generation/token, stale-result, credential-revision, pending-work, prefetch, and shutdown behavior;
- byte-bounded `ImageCache`;
- `ReadingStateStore`;
- `ImageViewer` and the QImage/QThread-based Qt pipeline;
- folder, PDF, thumbnail, spread, trim, and source-immutability test contracts.

OS portability does not require Qt independence. Do not add a generic pixel buffer/thread layer, event bus, dependency-injection framework, UI-framework abstraction, or broad controller rewrite solely for portability. Do not rewrite `ImageWorker` or fork platform-specific reader flows.

## 4. Unified source-open boundary

All supported entry points must converge on one application-level operation:

```text
startup argv
macOS QFileOpenEvent / Finder Open With
in-app File/Open
drag and drop
        |
        v
open_source(path)
        |
        v
existing provider selection and MainWindow reader flow
```

A small `ArchiveLensApplication`/service seam is allowed. Separate macOS, Windows, drag/drop, and CLI reader implementations are not.

Finder document declarations are limited to `.cbz`, `.cbr`, `.zip`, `.rar`, `.7z`, and `.pdf`. Folders remain available through Open Folder and drag/drop. Direct image declarations are out of scope until a separately designed `SingleImageContentProvider` exists.

## 5. First gate: macOS arm64 + Linux compatibility/backend spike

Issue #42 is the first implementation gate. Its original spike ran from v1.2.0;
the narrow delta revalidation runs from the exact v1.2.2 implementation baseline
before broad platform refactors, UI work, or production packaging.

Use the v1.2 dependency/toolchain set first. Validate on real macOS arm64 and Linux environments:

- source startup, Qt Widgets, settings/data paths, and test-suite behavior;
- ZIP/CBZ, 7Z, folder, PDF, and decoder behavior;
- exact RAR/CBR failure points and candidate native-library strategies;
- symlink/path/case behavior;
- native-library architecture and redistribution constraints;
- frozen and non-frozen runtime/backend discovery assumptions;
- existing Ubuntu CI expectations.

Build a **minimal frozen diagnostic** on macOS arm64 and Linux. It is not a release-quality app or Linux package. It must expose frozen-layout failures involving Qt plugins/frameworks, QtPdf, Pillow native modules, runtime paths, and candidate RAR libraries before #43–#46 commit to an architecture.

Produce `docs/MACOS_BACKENDS.md` and a Linux section or companion record with exact baseline, tested OS/architecture/tool versions, source and minimal-frozen results, backend/license/redistribution status, blockers, selected remediation, and RAR Go/No-Go evidence. Classify each backend as works / packaging change required / replacement required / unsupported.

No production feature rewrite belongs in the spike beyond minimal probes, fixtures, and diagnostics required for evidence.

## 6. Dependency policy

Start with the v1.2 dependency ranges and versions represented by `v1.2.0`. Keep Python, PySide6/Qt, Pillow, PyInstaller, py7zr, pyzipper, and native backends frozen/minimally changed during the spike.

Upgrade only for a documented macOS/Linux blocker. Isolate each upgrade and record the blocker, smallest viable change, license impact, and Windows/macOS/Ubuntu regression evidence. Do not combine the OS port with broad toolchain modernization.

## 7. Narrow platform seams

After #42, isolate only proven platform-specific behavior:

- frozen/source runtime roots and native backend loading;
- application data/settings/cache locations;
- filesystem case, symlink, and reparse behavior;
- desktop open events and document metadata;
- artifact naming/platform capabilities;
- release packaging, signing, and verification.

Keep platform branches out of provider/worker/viewer logic. Packaged self-test and diagnostics must use the same runtime-path abstractions as production code.

## 8. RAR/CBR backend and Go/No-Go gate

Keep `RarArchiveProvider` archive-facing and move ABI/loading details behind a platform-neutral backend:

```text
RarArchiveProvider
        |
        v
RarBackend
  |-- Windows UnRAR backend
  |-- macOS arm64 UnRAR backend
  `-- Linux backend/qualification path
```

Preserve Windows behavior, documented RAR4/RAR5/CBR/Unicode support, encrypted/solid handling, session-only credentials, bounded requested-entry reads, source immutability, and deterministic source/frozen discovery. Passwords must never enter process arguments, logs, settings, or reports. Normal reading must not require whole-archive or user-visible extraction. Record exact backend version, architecture, source, license, and redistribution evidence.

RAR is a formal release gate. **Issue #44 completed this gate with Go.** The approved
path uses pinned official UnRAR 7.23 behind the platform-neutral `RarBackend`; Windows
x64, macOS arm64, and Linux x64 source/minimal-frozen real-fixture qualification passed.
The Go decision clears #46 application bundling while Linux packaging remains deferred.

The gate policy remains:

- **Go:** a macOS arm64 backend passes security, resource, packaging, architecture, and redistribution checks. RAR parity remains mandatory.
- **No-Go:** no acceptable backend exists. Stop dependent RAR/package/release work and obtain an explicit scope decision in #32. Do not silently make RAR optional, use an unsafe CLI/password workaround, or weaken extraction/resource guarantees.

Linux RAR evidence belongs in the compatibility record even though Linux packaging is deferred. Do not claim Linux RAR support without source/runtime tests.

## 9. Codec and QtPdf qualification

**Issue #45 qualification is complete.** macOS 15 arm64 source and minimal-frozen
production-path checks passed for the shipped v1.2.2 decoder matrix and QtPdf,
including password PDFs, thumbnails, bounded high-DPI rendering, malformed/oversized
handling, and the v1.2.2 opaque-white page contract. Final distributable `.app`
inclusion remains owned by #46.

Qualify/package on macOS arm64: JPEG/PNG/WebP/BMP/GIF, TIFF, AVIF, JPEG 2000/JP2/J2K/J2C, and QtPdf including password PDFs, thumbnails, and bounded high-DPI rendering.

Verify native architecture, source/frozen discovery, fixtures, thumbnails/full decode, malformed/oversized input, existing orientation/alpha/profile behavior, resource guards, licenses, and missing-backend behavior. Reuse `DecoderRegistry` and `PdfContentProvider`. HEIC/HEIF and JXL remain deferred.

## 10. macOS arm64 application bundle

Create a reproducible `ArchiveLens.app` that launches on a clean macOS arm64 system without Python, Homebrew, MacPorts, or manual `PATH` setup. Include required Qt frameworks/plugins, shipped codecs/PDF runtime, approved RAR backend, notices/licenses, self-test resources, identifier, icon, version, build-info, and architecture metadata.

Keep Windows packaging green. Provide an unsigned/ad-hoc local **development** path. Finder declarations, notarization, and final DMG publication remain in their later issues.

## 11. macOS integration and Retina/path qualification

Use Qt standard keys/menu roles where practical. Route startup/Finder/file-dialog/drag-drop input through `open_source(path)`. Validate cold and already-running Finder opens for approved archive/PDF types without taking over defaults.

Retain the v1.2 Actual Size contract: **one image pixel maps to one physical display pixel**. Qualify Retina/external-display transitions, fit modes, thumbnails, PDF render/cache identity, zoom/pan/fullscreen, double-page layout, existing trackpad behavior, Unicode/case/path handling, symlink loops, removable volumes, and reading-state identity. This is qualification, not a new gesture system or zoom redesign.

## 12. Platform-neutral build-info and verification

The common machine-readable build-info contract must include at least:

```text
schema_version
version
source_commit
channel
os
architecture
artifact_kind
python_version
pyside_version
qt_version
native_backends
```

Common verification covers exact version/source commit, channel, checksums/manifest, expected files, notices/licenses, required source bundles, and cross-platform security assertions. Platform verifiers extend it:

```text
common release verifier
  |-- Windows portable/installer verifier
  |-- macOS app/DMG/signing/notarization verifier
  `-- future Linux package verifier (not a v1.3 deliverable)
```

Do not turn one Windows-shaped verifier into scattered OS conditionals. Windows verification remains first-class.

## 13. Signing, notarization, DMG, and fail-closed policy

Development builds may be unsigned/ad-hoc signed and must be marked non-release.

Every **official macOS v1.3 artifact** must be Developer ID Application signed (including nested code), hardened-runtime compliant, notarized, stapled, verified, and packaged as `ArchiveLens-<version>-macos-arm64.dmg`.

Official publication is fail-closed. Missing credentials, signing/notarization/staple failure, or verification failure must fail the macOS release gate. An unsigned/ad-hoc artifact must never be promoted as the official macOS release. Secrets stay outside source, logs, and artifacts.

## 14. CI and release automation

Required lanes:

- Windows source tests plus portable/installer packaging and verification;
- Ubuntu/Linux source tests with Qt offscreen support, preserving existing compatibility;
- macOS arm64 source tests, diagnostics, `.app`, packaged self-test, native architecture/runtime inspection, and DMG checks;
- credential-free PR/development paths separated from protected official signing/notarization jobs.

Smoke data covers shipped v1.2 parity only; HEIC/JXL are not "new codec" blockers. Failures remain visible and cannot produce an apparently complete partial release. Official `.app`/DMG builds run on macOS.

## 15. Target release artifacts

```text
ArchiveLens-1.3.0-windows-x64.zip
ArchiveLens-1.3.0-setup-x64.exe
ArchiveLens-1.3.0-macos-arm64.dmg
```

Source, wheel, sdist, notice, upstream-source, checksum, manifest, and build-info artifacts follow the common contract. No Linux package, macOS Intel, Universal2, or Mac App Store artifact is required.

## 16. Regression and release gate

Before tagging/publishing v1.3.0:

- run applicable v1.2 regressions on Windows x64 and macOS arm64;
- keep Ubuntu source CI green;
- verify archives/passwords, approved RAR, folders, PDF, shipped codecs, GIF, thumbnails, reading state, fit/trim, rapid navigation/source switching;
- verify immutability, credential redaction, no extraction leftovers, bounded work, and stale-result behavior;
- verify Windows portable/installer and macOS signed/notarized/stapled DMG from the exact release commit;
- verify common metadata/manifests/checksums and platform assertions;
- update user/developer/backend/license/release documents and record actual tested systems honestly.

No tag/release may be created while the RAR decision, official macOS signing/notarization, exact-commit CI, artifact verification, or any required supported-platform gate is unresolved.
